# Feature Specification: `did help hooks` Topic Documentation Command

## Overview
Proposes adding a `did help hooks` subcommand (or topic help) to display built-in user and agent documentation regarding lifecycle hooks (`.hooks/show`, `.hooks/done`, `.hooks/mv`, `.hooks/add`, `.hooks/status`, `.hooks/link`).

---

## Detailed Requirements

### 1. Command Invocation
- Running `did help hooks` (or `did help`) displays built-in guidance on how lifecycle hooks work.

### 2. Documentation Content Output
- **Hook Naming & Extensions**: Explains `.hooks/<event>` naming rules (e.g. `.hooks/show.sh`, `.hooks/show.md`).
- **Hook Discovery & Precedence**: Explains top-down ancestor traversal from `.did/` root to target task directory.
- **Hook Execution Rules**:
  - **Executable scripts** (Unix `0o111` mode): `did` executes script and prints stdout/stderr. Non-zero exit code aborts primary command.
  - **Non-executable files**: `did` prints path header and static text content to `stdout`.
- **Supported Hooks**:
  - `add`: Executed during task creation in `did add <PATH>`.
  - `show`: Executed/rendered during `did show <PATH>`.
  - `status`: Executed during status queries in `did status [PATH]`.
  - `done`: Executed before task completion in `did done <PATH>`.
  - `link`: Executed during symlink creation in `did link <TARGET> <DEST>`.
  - `mv`: Executed before moving/renaming in `did mv <OLD> <NEW>`.
  - `rm`: Executed before removing in `did rm <PATH>`.
  - `query`: Executed during search in `did query <QUERY>`.
  - `test`: Executed during repository health check in `did test`.
  - `help`: Executed during `did help [TOPIC]`.
