# `did init` Subcommand

## Overview
A dedicated `did init` subcommand to initialize the `.did/` state directory in the target directory (defaulting to the current working directory).

## Requirements
- [x] Add `Init` subcommand to `did` CLI.
- [x] Initialize empty `.did` state directory in specified directory or current working directory.
- [x] Return error if `.did` directory already exists.

## Acceptance Criteria
- [x] Running `did init` creates `.did/` directory and outputs success message.
- [x] Running `did init` when `.did/` exists outputs error and exits non-zero.
- [x] Running `did init <PATH>` creates `.did/` inside `<PATH>`.

## Test Plan
- [x] Unit and integration tests verify `did init` functionality across scenarios.
